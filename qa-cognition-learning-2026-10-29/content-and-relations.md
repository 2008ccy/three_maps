# 认知地图内容与关系清单

4 个主题、19 个教学条目、19 条归属、32 条知识与反馈联系（21 核心，11 扩展），20 条跨图联系。保留原 5 条指导与反馈方向；无向比较 2 条。

## 三个观

从什么角度看待一个判断？

| ID | 条目 | 学习角色 | 学完能做什么 |
| --- | --- | --- | --- |
| system-view | 系统观 | 认识视角 · 看结构与联系 | 把一句“模型答错了”拆成可以追查的环节，而不是立刻换模型。 |
| development-view | 发展观 | 认识视角 · 看变化与边界 | 说明新方法缓解了什么限制，同时指出它没有解决什么。 |
| third-view | 求真观 | 认识视角 · 查证与反例 | 区分资料说了什么、自己推断了什么，以及怎样改变判断。 |

## 分析方法

怎样让判断经得起比较和反例？

| ID | 条目 | 学习角色 | 学完能做什么 |
| --- | --- | --- | --- |
| system-analysis | 系统拆解 ＋ 反例检查 | 分析方法 · 拆环节与找反例 | 把宽泛结论改成可以逐环核对、能被反例约束的问题。 |
| loss-test | 案例① 损失下降 ≠ 回答更好 | 分析案例 · 检查替代指标 | 解释训练信号与独立任务收益之间还缺哪些证据。 |
| comparison | 对照比较 ＋ 问题定义 | 分析方法 · 先定义再对照 | 写出公平比较所需的共同任务、设置和判分口径。 |
| ranking-task | 案例② 榜单排名 ≠ 适合答疑 | 分析案例 · 从榜单回到任务 | 说明通用排名能用于初筛，却还不能证明适合课程答疑。 |
| tradeoff-method | 多目标取舍 ＋ 演进分析 | 分析方法 · 比收益与代价 | 在共同质量要求下，说明选项的代价、约束与未知项。 |
| cost-api | 案例③ 效果与成本的取舍 | 分析案例 · 约束下作选择 | 写出包含质量、运行与维护边界的选择理由，而非确定账单。 |

## 成长习惯

怎样把一次分析变成可重复行动？

| ID | 条目 | 学习角色 | 学完能做什么 |
| --- | --- | --- | --- |
| define-problem | 先定义问题 | 成长习惯 · 任务卡 | 在选工具前写清读者、输入输出和验收条件。 |
| check-evidence | 找依据和反例 | 成长习惯 · 证据卡 | 为重要判断保留可定位出处、适用条件及可能反例。 |
| small-trial | 小规模试跑 | 成长习惯 · 最小复验 | 设计规模小但能留下输入、输出与失败记录的一轮检查。 |
| learn-from-gaps | 从困难反查知识 | 成长习惯 · 缺口回路 | 把不理解的点连到具体知识，并回到同一任务复验。 |
| weekly-review | 每周分工与检查 | 成长习惯 · 可追踪协作 | 把修改、复核和未解决问题写成可检查的记录。 |
| independent-feedback | 独立反馈再修订 | 成长习惯 · 外部检验 | 把访客意见转成可复核的问题，再决定是否修改。 |

## 认识修正

什么证据让你改变了哪一部分判断？

| ID | 条目 | 学习角色 | 学完能做什么 |
| --- | --- | --- | --- |
| revision-before | 原来怎样理解 | 认识修正 · 保留原判断 | 把原判断、当时依据与适用范围写清，留下可比较起点。 |
| revision-evidence | 什么带来变化 | 认识修正 · 指认变化依据 | 说明哪一条证据改变了原判断，以及证据能支持多大范围。 |
| revision-after | 现在怎样理解 | 认识修正 · 更新有条件结论 | 把新判断写得比旧判断更有边界，并能解释相应行动变化。 |
| revision-open | 仍不知道什么 | 认识修正 · 未知与下一步 | 把未确认项变成可行动的问题，而不是用推测补满。 |

## 关系与边界

| 起点 | 关系 | 终点 | 类型 | 说明、条件与不能推出的结论 |
| --- | --- | --- | --- | --- |
| 三个观 | 指导选方法 | 分析方法 | 原方向 / 核心 | 原关系图的指导方向：认识视角帮助选择具体分析方法，不是按某个视角必然得到正确答案。 |
| 案例① 损失下降 ≠ 回答更好 | 跑过后修正 | 认识修正 | 原方向 / 核心 | 原关系图的反馈方向：实际取得训练与独立任务记录后再修正；本页教学推演不表示已经跑完实验。 |
| 案例② 榜单排名 ≠ 适合答疑 | 跑过后修正 | 认识修正 | 原方向 / 核心 | 原关系图的反馈方向：课程同题比较可能改变原有选型判断；还需要保存设置和逐题依据。 |
| 案例③ 效果与成本的取舍 | 跑过后修正 | 认识修正 | 原方向 / 核心 | 原关系图的反馈方向：取得质量、用量与投入证据后再更新取舍理由，不编造账单或收益。 |
| 认识修正 | 反哺习惯 | 成长习惯 | 原方向 / 核心 | 原关系图的反馈方向：有依据的认识变化应影响下一轮执行规则；不自动说明习惯已经长期形成。 |
| 系统观 | 指导逐环拆解 | 系统拆解 ＋ 反例检查 | 教学联系 / 核心 | 从整体联系转为交接检查；视角帮助选择方法，不保证拆解本身已经定位原因。 |
| 求真观 | 指导寻找可能反例 | 系统拆解 ＋ 反例检查 | 教学联系 / 核心 | 先明确要检验的主张和证据范围；反例用于约束结论，不表示一概否定所有方法。 |
| 发展观 | 引导演进与取舍比较 | 多目标取舍 ＋ 演进分析 | 教学联系 / 核心 | 在同一问题下检查新方法改变的限制和新增条件；新旧顺序不能推出优劣。 |
| 求真观 | 提醒回查依据与条件 | 找依据和反例 | 教学联系 / 扩展 | 重要结论回到原文或原记录；附有链接不能自动升级为已核实。 |
| 系统拆解 ＋ 反例检查 | 用独立问题检查训练收益 | 案例① 损失下降 ≠ 回答更好 | 教学联系 / 核心 | 本例用拆解与反例区分训练信号和任务结果；这是待执行框架，不是实验成功报告。 |
| 对照比较 ＋ 问题定义 | 用固定任务复核排名 | 案例② 榜单排名 ≠ 适合答疑 | 教学联系 / 核心 | 先统一任务和判分，再解释榜单与课程要求的差异；不由一次比较推导普遍冠军。 |
| 多目标取舍 ＋ 演进分析 | 用共同口径比较投入 | 案例③ 效果与成本的取舍 | 教学联系 / 核心 | 在相同质量要求下保留设备、用量与人工边界；缺少记录时不能给出确定最低费用。 |
| 先定义问题 | 先确定比较对象与标准 | 对照比较 ＋ 问题定义 | 教学联系 / 核心 | 任务卡为比较提供读者、输出和验收条件；定义任务不等于候选方案已满足它。 |
| 找依据和反例 | 为改变判断提供可追溯依据 | 什么带来变化 | 教学联系 / 核心 | 应能定位出处、对象与条件；反对意见或个人感受需要先核实，不能直接写成事实。 |
| 小规模试跑 | 提供待核对的逐题记录 | 案例① 损失下降 ≠ 回答更好 | 教学联系 / 扩展 | 实际试跑需保存环境和失败，手工推演另行标明；少量成功不能证明所有课程问题有效。 |
| 小规模试跑 | 提供条件与投入记录 | 案例③ 效果与成本的取舍 | 教学联系 / 扩展 | 成本需关联实际用量、质量和维护条件；只记录一次调用费用不能代表总成本。 |
| 独立反馈再修订 | 提供需复核的失败线索 | 什么带来变化 | 教学联系 / 核心 | 保留读者原问题与使用条件，再对照来源决定修订；意见不自动变成正确答案。 |
| 案例① 损失下降 ≠ 回答更好 | 显化原有训练判断 | 原来怎样理解 | 教学联系 / 扩展 | 若原判断把训练指标当作全部质量，先保留原句与依据；本教学初始判断不是成员真实经历。 |
| 案例② 榜单排名 ≠ 适合答疑 | 显化榜单选型假设 | 原来怎样理解 | 教学联系 / 扩展 | 把“排名高就适合”写成可检查主张，而非事后重写起点；没有比较记录时仍不能宣布选型结果。 |
| 案例③ 效果与成本的取舍 | 暴露未知资源条件 | 仍不知道什么 | 教学联系 / 扩展 | 缺少用量、设备与人工记录时保留未知；缺证据不等于证明某条路线不可用。 |
| 原来怎样理解 | 对照原判断寻找变化依据 | 什么带来变化 | 教学联系 / 核心 | 新依据应针对原主张的对象和范围；仅列更多资料不能说明为什么需要修正。 |
| 什么带来变化 | 在成立范围内更新判断 | 现在怎样理解 | 教学联系 / 核心 | 说清证据支持保留、撤回或增加哪些条件；教学材料不自动成为实际实验结论。 |
| 现在怎样理解 | 保留新结论未覆盖之处 | 仍不知道什么 | 教学联系 / 核心 | 修正后的判断仍有条件和未知，不应为了闭环而填成普遍结论。 |
| 仍不知道什么 | 把未知转为具体学习任务 | 从困难反查知识 | 教学联系 / 核心 | 每个缺口对应所需概念、材料或复验动作；列出待办不等于已经完成学习。 |
| 从困难反查知识 | 学习后回到同一任务复验 | 小规模试跑 | 教学联系 / 核心 | 检验新知识是否解除原困难，保存前后差别；看完教程不能直接代替复验。 |
| 现在怎样理解 | 形成可追踪的修改记录 | 每周分工与检查 | 教学联系 / 扩展 | 记录改前改后、依据与复核者；完成编辑不等于知识内容已核实。 |
| 每周分工与检查 | 把修改交给独立读者复查 | 独立反馈再修订 | 教学联系 / 扩展 | 先观察独立使用，再解释与讨论；计划中的访客检查不能写成已经收集的反馈。 |
| 找依据和反例 | 为反例检查保留证据 | 系统拆解 ＋ 反例检查 | 教学联系 / 扩展 | 反例应与具体主张、条件及输入输出相连；孤立失败不能直接归因于模型能力。 |
| 系统观 | 互补观察结构与变化 | 发展观 | 无向比较 / 扩展 | 两种视角关注不同侧面，可以组合；无箭头表示互补，不表示其中一种是另一种的技术前置。 |
| 案例① 损失下降 ≠ 回答更好 | 共同警惕替代指标冒充任务质量 | 案例② 榜单排名 ≠ 适合答疑 | 无向比较 / 扩展 | 训练指标和通用名次都需回到课程要求核对，但它们不是同一指标，也不要求得到相同结果。 |
| 先定义问题 | 提供小试验的验收条件 | 小规模试跑 | 教学联系 / 核心 | 明确哪些输出算满足需求，失败如何留痕；任务卡不能代替真实运行记录。 |
| 现在怎样理解 | 反哺习惯 | 成长习惯 | 教学联系 / 核心 | 把有依据的新判断转成后续执行规则，并继续复验；这里只保留原反馈方向，不宣称习惯已经形成。 |

全部关系依据为 L7 / L5，原方向与编辑教学联系分别标注；附来源不代表已独立核实。逐条来源、跨图目标、教学推演及路线见 JSON。
