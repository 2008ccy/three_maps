# 生态地图素材

核实日期：2026-10-25　　数据来源：GitHub API、各项目官网

## 一、分层方式

计划书对生态地图的要求：覆盖模型团队、开源社区、数据集、训练框架、评测工具、算力及部署服务；分析开放模型与工具如何协作、资源成本由谁承担。

按一个模型从训练到可用的流转顺序切成八层：

| 层 | 内容 | 代表 |
|---|---|---|
| 1 | 模型团队 | 阿里 Qwen、智谱、月之暗面、DeepSeek、Meta |
| 2 | 开放权重模型 | Qwen3.8、GLM-5、Kimi-K3、DeepSeek-V3、Llama |
| 3 | 权重与数据集分发 | 魔搭、Hugging Face、hf-mirror、Ollama 库 |
| 4 | 训练与微调框架 | PyTorch、Transformers、PEFT、TRL、DeepSpeed、LLaMA-Factory |
| 5 | 推理与部署 | vLLM、SGLang、llama.cpp、Ollama |
| 6 | 评测 | lm-evaluation-harness、OpenCompass、C-Eval、LMArena |
| 7 | 算力与云服务 | 阿里云百炼、硅基流动、自建 GPU |
| 8 | 应用与终端 | Dify、Open WebUI、qwen-code |

关系取五种类型：发布、托管、适配、付费、评测。

## 四、两条关系分析

### 1. Qwen3.8 链路的成本分摊

链路：Qwen 团队训练 → 权重开源 → 魔搭 / HF / Ollama 分发 → Transformers、vLLM、llama.cpp 适配 → 百炼、硅基流动按 token 出售 → 应用层调用。

| 环节 | 承担方 | 承担内容 |
|---|---|---|
| 训练 | 阿里 | GPU、数据、人力；单次为千万美元量级（业界公开估算，未核实） |
| 存储与带宽 | 魔搭、HF、hf-mirror、Ollama | 纯成本，对用户免费 |
| 适配 | 开源社区及各公司工程师 | 人力时间，通过 issue 与 PR 推进 |
| 推理 | 使用者 | 按 token 付费，或自购显卡承担电费 |
| 集成 | 项目方 | 一次开发成本，加每月少量 API 费用 |

结论：开源模型把训练成本集中在少数机构，把推理成本分摊给每个使用者。免费的是权重文件，不免费的是算力与电力。课程项目感知不到训练成本，是因为该成本已由发布方承担。

### 2. Llama 系列的相对衰退

事实（截至 2026-10-25）：

一，meta-llama/llama-models 最近一次 release 为 v0.2.0（2025-04-05），仓库最后推送 2026-02-11。

二，同期 GLM-5 于 2026-10-15 更新，Qwen3.8 最后推送 2026-08-17，MoonshotAI 在发布 Kimi-K3 与 K2.5。

三，Ollama 仓库官方简介列举的模型为 Kimi、GLM、MiniMax、DeepSeek、gpt-oss、Qwen、Gemma，未列出 Llama。

四，本次抓取中魔搭可访问，Hugging Face 未连通。此项与模型本身无关，但影响实际使用分布。

推断（依据上列四条，尚无官方说法）：开源模型的重心可能已转向中国厂商开源模型与 gpt-oss 一侧，涉及中文场景适配、国内分发速度、许可证策略三方面。

对选型的含义：Qwen3.8 或 GLM-5 在中文与国内下载渠道上更稳妥；Llama 资料存量多但更新缓慢。最终仍需以实测效果为准。

## 六、对本项目的选型含义

| 用途 | 采用 | 依据 |
|---|---|---|
| 网站 AI 问答 | 百炼或硅基流动 | 国内直连，无需自购算力，与计划书「先调外部 API」一致 |
| 本地试运行 | Ollama 拉取 qwen3.8 | 命令简单，占用内存与显存 |
| 微调实验 | PEFT + TRL，或 LLaMA-Factory | 小显存可完成 LoRA，满足报告需要 |
| 效果评测 | lm-evaluation-harness，中文用 C-Eval 或 OpenCompass | 客观题易量化，答疑质量仍需人工抽查 |

计划书所选服务器为 2 核 4G CPU 实例，无 GPU，无法运行可用于问答的中等以上模型（7B 量级起）。网站只能调用外部 API，模型训练须另配机器。
