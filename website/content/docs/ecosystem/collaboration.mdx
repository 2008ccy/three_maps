## 核心协作链

| 环节 | 谁负责 | 交给下游什么 |
| --- | --- | --- |
| 模型与研究来源 | 模型团队、研究者 | 模型对象、方法依据和使用条件 |
| 运行与工具 | 工具维护者、服务方或自托管者 | 可用的运行路线、接口与异常约定 |
| 应用与资料 | 资料提供者、应用团队 | 问题、支持片段、回答与引用 |
| 评测与验收 | 项目成员、评测工具 | 固定设置、逐题结果与失败原因 |
| 反馈与维护 | 读者、内容维护者 | 经核实的问题、修订和复测记录 |

这是教学组织路线，评测会贯穿开发；使用托管 API 不要求本组下载权重，适配也按实际问题决定。[L8](ref:L8)

## 工具只记职责

Transformers 提供加载与生成接口；PEFT 提供参数高效适配实现；TRL 的 SFTTrainer 组织监督微调流程。SFT 是任务，LoRA 是更新方法，二者可以配合。[S05](ref:S05)—[S07](ref:S07)、[S26](ref:S26)

## 应用交付的最小链路

**问题 → 检索片段 → 模型回答 → 引用展示 → 失败反馈。** RAG 提供外部依据的设计思路；资料与引用仍需核对。[S02](ref:S02)
