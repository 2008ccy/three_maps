# 三张活地图网站 · 维护说明

本目录是独立的 Fumadocs + Next.js + TypeScript 项目。正文在 Markdown/MDX 文件中，构建后由 GitHub Pages 提供静态页面。使用系统字体、本地图片及本地搜索索引，浏览不需要登录或模型密钥。

## 1. 运行和预览

推荐 Node.js 24 LTS，使用项目内的 `package-lock.json` 固定依赖版本。

```sh
cd website
npm ci
npm run dev
```

开发地址通常是 `http://127.0.0.1:3000`。若端口占用，按终端实际显示的地址访问。

生产静态预览：

```sh
npm run check
npm run build
npm run check:export
npm test
npm run preview
```

验证 GitHub Pages 子路径（macOS/Linux）：

```sh
NEXT_PUBLIC_BASE_PATH=/three_maps npm run build
npm run check:export
npm test
npm run preview
```

PowerShell 可先执行 `$env:NEXT_PUBLIC_BASE_PATH="/three_maps"`，再执行 `npm run build`。预览服务器读取本次构建的路径配置，会打印准确地址；默认 3000 端口，`PORT=3001 npm run preview` 可换端口。

当前显式采用 Next.js Webpack 构建，以兼容本机受限环境；不需要自行安装独立服务器。`out/` 是生成物，不直接修改或提交。

## 3. 修改或新增一篇内容

### 领域地图教学内容

- `src/lib/maps/domain-learning.ts` 维护5个主题、18个具体知识点、18条归属关系与22条概念联系（12条核心、10条扩展、其中3条无向比较），并单独记录18步建议学习顺序。旧节点ID保留；`finetuning`现为监督微调SFT，新增`lora`、`retrieval`、`inference`。教学分类和建议顺序不表示必然技术依赖。
- `src/lib/maps/teaching-case.ts` 是贯穿案例的3段自编材料。每个节点的`lesson`提供目标、解释、输入—过程—输出示例、辨析、理解检查与可选进阶块；示例不冒充课程原文、模型实测或已完成的实践。理解检查只展开解析，不记录成绩或改写资料状态。
- `DomainExplorer`及`DomainGraph`只服务领域地图；其余两图继续使用原组件。领域地图保留主题浮层、两列小卡片、单列720px/17px正文、内部滚动和固定上下导航。筛选搜索包含教学内容；高级筛选默认折叠。全部关系模式使用`relations=all`查询参数；`view`、筛选和`#node-…`继续支持分享及前进后退。
- `MapNode.lesson/topic`、`MapDefinition.learningPath/conceptRelations`均为可选字段，旧地图保持兼容。概念关系逐条记录说明、来源、核心标记、方向及材料关系/编辑建议；依据与核实状态分开，不自动升为已核实。地图不恢复完整文章入口。
- `domain-lesson.tsx`统一渲染教学内容，检查解析和进阶区采用原生details，静态导出无脚本仍可阅读。`allowImportingTsExtensions`配合现有Node原生TypeScript测试；没有新增运行依赖。

### 粒子曲面首页

首页采用方案 09 的深色粒子曲面设计：左侧呈现课程助手的问题，右侧呈现金色、青色、珍珠白三层粒子曲面，下方以三个编号入口进入领域、生态、认知地图。顶部从左侧依次横向排列品牌、领域、生态、认知、更新记录、资料来源、反馈及搜索入口。手机首行的品牌与搜索靠左，第二行的六项导航同样靠左，空间不足时自然换行。导航、搜索和三张地图首次访问即显示，无需点击激活，也不依赖会话存储。原探索路线及下滑提示继续暂停展示。

- `src/app/(home)/page.tsx` 维护首屏文案、地图入口和页脚；`home-content.ts` 统一维护地图名称、说明与地址。
- `src/app/(home)/home-experience.tsx` 负责首页布局与返回时的转场就绪标记。`src/components/home-scene-state.tsx` 初始即为 `expanded`，保留减少动态效果检测和地图返回兼容逻辑。
- `src/app/(home)/home-particles.tsx` 使用原方案的粒子画面作为纹理，以 GPU 局部位移呈现三个曲面错开、不规则的流动，保留原图的点云密度、曲面层次、景深和配色。文字、导航、按钮和标注由独立 HTML 元素呈现，不随纹理扭曲；未新增运行依赖。
- `src/app/(home)/home.module.css` 维护深墨蓝背景、暖白文字、细分隔线及桌面和手机布局。三张地图的主题卡、关系图和阅读浮层沿用同一套视觉样式，领域以金色、生态以青色、认知以珍珠白区分。
- 首页按 `100svh` 分配导航、主视觉、三个地图入口及页脚，粒子区域随剩余空间缩放；手机三个入口并排。首页范围内覆盖 `body` 的视口最小高度，避免手机地址栏产生额外空白；极矮窗口保留自然滚动以确保操作可达。三图和正文仍使用原有可滚动布局。
- 系统开启“减少动态效果”时使用静态粒子画面；GPU 或 Canvas 不可用时保留静态图片。装饰画面不截获点击；无 JavaScript 时，标题、导航和三个地图入口仍能直接阅读与访问。
- `scripts/test-home.mjs` 检查静态导出首页的立即可见导航、三张地图链接、顶部搜索入口及未启用的转场层。浏览器验收需覆盖 1366×768、1440×900、1920×1080 和 390px 窄屏，验证搜索、地图进入与返回、无脚本、减少动态效果以及页面无横向溢出。

### 文档正文

普通段落、列表、表格按 Markdown 写。文件后缀为 `.mdx`，只有使用卡片等交互组件时才需要 JSX。正文以标题、简介和内容元信息开场，不再额外展示“资料与项目 / 主题阅读”等泛化标签；地图归属仍由面包屑和返回入口表达。

新条目示例：在适合的地图目录中创建文件，替换以下内容。

```mdx
---
id: "K-NEW-CONCEPT"
title: "新概念"
description: "用一句话解释它的作用。"
updated: "2026-10-26"
status: "资料整理 · 理解程度待自评"
related: ["K-RAG", "C-RANKING"]
---

## 它是什么

解释概念，标清适用条件。依据见 [S02](ref:S02)。

## 与什么相关

它与 [RAG](node:K-RAG) 的关系是……

## 还不知道什么

列出缺少的证据，不把计划写成结果。
```

- `id` 全站唯一，建立后保持稳定。改标题不改 ID；移动文件后，`node:` 链接会自动找到新地址。
- `updated` 使用带引号的日期字符串，改内容时同步改日期。
- `status` 说明材料或实践状态；`related` 保留内容关联元数据，正文底部不再自动追加关联卡片。图内跨图关系由导图配置维护。
- 在同目录 `meta.json` 的 `pages` 数组中加入文件名（不带 `.mdx`）。顺序用于页面树与面包屑；`index` 是目录首页。侧边栏固定显示总览及五个顶层栏目，子页面通过导图、首页任务路线或搜索进入。
- 三张地图总览使用可展开导图，结构维护见下面“导图维护”；文档页的 `<NodeGrid ids={["D-TASK", "D-PIPELINE"]} />` 当前只展示条目名称和说明，不提供跳转。
- 使用二级标题 `##`，Fumadocs 自动生成本页目录和小节链接。

也可点击页面上的“编辑本页”进入 GitHub 编辑器。建议通过分支和 Pull Request 修改，检查通过再合并；合并到 main 后自动重建。

## 4. 来源、图片和公式

**来源：** 顶部“资料来源”与“更新记录”同级，指向 `/docs/sources/`，可直接查找本地素材、论文、课程和官方文档。正文引用仍可定位到对应来源编号。在 `sources/index.mdx` 新增 `## S22` 等唯一标题，写明原始入口、支持内容、版本/日期及局限。正文使用 `[S22](ref:S22)`。不要仅列论文名而不说明它支持什么。L1—L5 指向仓库原素材。

L6 是浙大版讲解稿，归档 PDF 放在 `public/sources/ai-model-building-zju.pdf`，知识树原图在 `public/images/domain/zju-knowledge-tree.png`。学校课程信息来自讲解稿转述，正式培养方案原件仍待核验。更新归档材料时同步 `map__text` 与网站副本。

L7 是用户提供的 `认知地图关系图.html`，原件归档于 `map__text`，网站在 `public/sources/cognition-relationships.txt` 提供原始 HTML 文本。认知地图保留四条主干，三个方法组合并入对应案例；六类习惯合为三组行动，四个修正问题合为三个步骤。原有内容与关系快照保存在 `future-updates/cognition-2026-11-02/`，便于恢复与后续更新。

**关系：** 正文使用 `[显示名称](node:稳定ID)`，例如 `[LoRA](node:K-LORA)`；不要手写完整域名或 `/three_maps`，避免更换部署地址后失效。普通站内链接使用 `/docs/...`。

三图旧正文之间的跳转已停用：`ContentLink` 将指向三图深层正文的链接渲染为普通文字，`NodeGrid` 对这些目标展示静态条目，关联阅读也过滤相同目标。来源引用、当前地图节点、项目页面、外部依据、页内锚点及返回地图仍可操作。旧正文地址与归属元数据保留用于兼容，不再由知识卡提供入口。

**图片：** 放入 `public/images`，正文使用 `![描述](/images/文件名.png)`。路径前缀由组件处理；点击图片可看原图。

**公式：** 行内用 `$...$`，独立公式用 `$$...$$`。KaTeX 在构建时渲染，字体随静态资源提供。MDX 中普通文本的花括号需要转义；公式放进数学标记内。

## 6. GitHub Pages 部署

### 共享反馈与发布配置

`/feedback/`提供公开反馈表单、筛选、分页和稳定编号入口；地图总览、主题、知识点和正文均有反馈入口，可带入当前有效对象。表单支持提交前预览、逐字段校验、错误焦点、失败保留内容及限流响应的重试倒计时；成功后进入该条详情。未配置服务时提交禁用，仍可预览，不用浏览器本地存储或演示记录代替共享数据。

当前本地配置使用 WorkBuddy 托管 PostgreSQL 数据面，网页通过 SDK 调用 `list_feedback`、`get_feedback` 和 `submit_feedback`。接入与受保护管理入口见[当前 WorkBuddy 说明](../feedback-cloud/WORKBUDDY-CLOUD.md)。2026-11-06 的只读检查已从真实服务取得列表与一条已有详情（均 HTTP 200）；这不等于本轮已验证写入、跨设备持久化、管理员回复或云服务额度。

GitHub Pages 自动构建不会读取本机未提交的 `.env.local`。在仓库 **Settings → Secrets and variables → Actions → Variables** 添加以下两个 Repository variables，再重新运行工作流：

| 变量 | 设置内容 |
| --- | --- |
| `NEXT_PUBLIC_WORKBUDDY_CLOUD_ENDPOINT` | 当前 WorkBuddy 应用公开 HTTPS endpoint |
| `NEXT_PUBLIC_WORKBUDDY_CLOUD_KEY` | 同一应用的 publishable key；仅使用可公开的应用标识 |

工作流会把这两项传给 Next.js 构建。不得填写数据库连接串、管理员凭据或服务器密钥。当前客户端优先使用配置完整且有效的 WorkBuddy 数据面；只有未启用此路径时，才回退到旧自建 HTTP 接口的 `NEXT_PUBLIC_FEEDBACK_API_BASE_URL` 与 `NEXT_PUBLIC_FEEDBACK_SERVICE_VERIFIED=true`。静态构建元信息只记录 `feedbackConfigured` 布尔值，不包含地址或凭据。发布后需实测正式域名的反馈列表，不能仅以该布尔值判断服务正常。

旧事件云函数、PostgreSQL 私有 schema 和传统 CloudBase 文档数据库适配器仍保留在[后端说明](../feedback-cloud/README.md)与[交接说明](../feedback-cloud/WORKBUDDY-HANDOFF.md)，其限频及白名单能力不应直接归于当前 SQL RPC 路径。`sql/003-workbuddy-targets.sql` 是本地准备的活动对象白名单补丁；需经受保护管理端审查并执行后才在真实数据库生效，本轮没有执行云端迁移。可信来源的业务限频仍需结合实际网关或服务器实现与验收。

活动对象清单位于 `feedback-cloud/data/targets.json`，与三图目录同步；`npm run check`核对目录及白名单迁移内容，地图内容变更时需同步。更新日志的 `UpdateEntry` 支持可选 `feedbackIds`；只引用真实反馈编号，实际发布后才填写 `releaseVersion` 和“已完成”。

网站测试包括前端反馈协议、禁用状态、旧适配器事务，以及当前托管 SQL RPC 的权限、幂等、分页、字段校验与本地白名单补丁。首次运行前执行 `npm --prefix ../feedback-cloud ci --ignore-scripts`；CI 也会安装锁定依赖。本地测试不代替真实设备 A/B、管理权限、平台来源限制及额度验收。本轮不自动提交、开通服务或发布。

默认仓库为 `2008ccy/three_maps`，目标地址为 `https://2008ccy.github.io/three_maps/`。该地址仅是配置目标，不表示已经上线。

1. 将网站文件与根目录 `.github/workflows/website.yml` 推送到仓库。
2. 在仓库 Settings → Pages → Build and deployment 中选择 **GitHub Actions**。
3. 工作流会安装依赖、检查内容和类型、构建、检查导出链接、运行搜索与跨图测试；全部通过后发布。
4. 首次发布后直接打开一个详情地址并刷新，验证图片和搜索；再用校园网及移动网络进行独立访问验证。

Pull Request 只检查和构建，不部署。构建或测试失败时不会触发发布，已上线版本保持不变。可恢复上一条已知可用提交再重新运行工作流回滚。若更换仓库名或使用根域名，调整工作流中的 `NEXT_PUBLIC_BASE_PATH`，并同步 `src/lib/shared.ts` 的 GitHub 编辑入口。

GitHub Pages 只负责静态页面。共享反馈当前由 WorkBuddy 托管数据库 RPC 处理，旧云函数适配器仍保留；后续 AI 接入需要服务端，密钥不能写入正文、浏览器代码或 `NEXT_PUBLIC_*` 变量。本版不增加用户登录或独立评论系统。

## 7. 检查项与已知边界

- `npm run check:content`：必填元数据、唯一 ID、关联、来源、图片和目录引用。
- `npm run types:check`：路由类型和 TypeScript。
- `npm run check:export`：实际导出的全部 HTML、站内链接、锚点、脚本及样式资源，包含部署前缀。
- `npm test`：读取导出的搜索索引、HTML 和导图配置，验证搜索、跨图路径、公式、节点引用与来源、锚点恢复、分支切换、无 JavaScript 层级入口以及课程同步。
- 浏览器人工验收：手机与桌面布局、鼠标导航、搜索结果点击、目录、夜间配色和长表格。

搜索索引在构建时生成，首次搜索会下载索引，以后在浏览器内查询。三图只索引当前活动节点，搜索结果直接定位地图中的知识卡；旧站介绍及三图旧正文不进入搜索。更新与来源等公共页仍可检索。构建和查询必须使用相同的 CJK 编码器，统一维护 `src/lib/static-search.mjs`。内容较多时再评估搜索服务。

完整作业还需要真实 AI、实验/分析证据、三名非组员反馈和上线后的国内网络验证。本次不代填这些结果。
