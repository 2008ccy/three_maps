## 第三次发布（19:50，HEAD = 6900d58，「不要动本地文件」模式）

- 用户要求不修改本地文件，于是全套在 `/tmp/tm-pub`（含 578 MB node_modules 实体复制，不软链）完成构建与发布，`website/` 全程只读。
- **关键坑：构建期 ECONNREFUSED `/var/folders/.../cbb-*/broker.sock`**。根因是环境变量 `NODE_OPTIONS=--require .../cli/vendor/shim/node-language-shim.cjs`，该 shim 把子进程的 net/fs 操作转发到 `CODEBUDDY_SANDBOX_BROKER_IPC_ADDRESS` 指向的 broker，而那个 socket 的监听进程早已退出（11-04 遗留的 stale socket）。build worker 随机某页一碰就挂，报错页面每轮不同，容易误判为页面代码联网。
- **解法**：`env -u NODE_OPTIONS -u CODEBUDDY_SANDBOX_BROKER_IPC_ADDRESS -u CODEBUDDY_DOCUMENT_IPC_ADDRESS npm run build`，加上 `NEXT_TELEMETRY_DISABLED=1`。build 10 秒完成（复用 node_modules 里的 webpack 缓存）。这个解法比「换目录」「降并发」有效，也解释了以往 `.next` 清理被拦的现象。
- **从临时目录发布的副作用**：`workbuddy_sites_deploy` 会把 `.wbapp_<id>.genie` 的 `localDir` 改写为传入的 directory（变成了 `/tmp/tm-pub/out`）。发完必须改回 `/Users/changyichen/Developer/projects/three_maps/website/out`，否则 `/tmp` 被清后绑定失效。appId 显式传入时分享链接与应用不变，已验证。
